# Read Regulations — the Regulation Firewall

## Dispatch the named agent — the contract lives in its body

This skill is a **thin main-session pointer**. The firewall *contract* — the boundary, the gate-defined read loop, the citation-fidelity gates, the render-cleanup gate, the cache protocol, and the `<thalura-digest version="1">` envelope mandate — is the fixed system prompt of the named agent **`agents/read-regulations.md`**. It is **not** restated here and is **not** relayed in the dispatch prompt.

**When a firewall read is needed, the main session dispatches the named agent: `subagent_type: "thalura:read-regulations"`** (the Agent-tool dispatch handle). This is a hard mandate, not a suggestion: do **not** hand-write a `general-purpose` firewall prompt that restates the boundary or the read loop — the contract is single-sourced in the named agent's body, and dispatching it by name is how that single source takes effect. **Fan out — dispatch one named `thalura:read-regulations` reader per document in the dispatched set, all in ONE tool batch; each reader receives exactly one document with its `Read scope`, its matching page-map sidecar slice, and the regulatory-hierarchy context; each reader's dispatch prompt begins with exactly one `document_id:` line — the registry id of its single document** (the same four read inputs as before — now sliced per document, never the whole plural set to one reader). The dispatched set is the registry-resolved INCLUDE set minus every document whose needed sections are already covered by a version-stamp-valid cache entry. Concurrency is gate-defined (whole batch; escalate to sequential waves only on an observed queue/reject/fail-to-start; every dispatched document returns a verified digest — none silently dropped). Each reader returns **only its own document's digest**; nothing else crosses back.

**Graceful-degradation backstop.** If the named dispatch does not resolve, the dispatch falls back to `general-purpose`. On that fallback path a host-executed `PreToolUse`-on-`Agent` hook injects the envelope mandate into the dispatched prompt, so the `<thalura-digest version="1">` envelope emission stays in force regardless. A missed named dispatch is therefore **no worse than the prior behaviour** — the digest still comes back enveloped (host-hook persistence applies on the CLI runtime; the in-runtime persist path that also covers the isolated-VM runtime requires the named firewall agent).

## The cache round-trip is agent-executed and internal

The session digest cache lets downstream tasks reuse a digest without re-running the heavy read. The **agent runs the round-trip itself, through its shell** — a `get` before the read and a `put` after, against the shipped helper `${CLAUDE_PLUGIN_ROOT}/scripts/cache.py`, keyed off the section identity it resolves. This is what makes persistence work in **both** runtimes: a host-executed cache hook does not fire reliably in the Cowork host/VM split, so the agent persists on its own initiative. (Host cache hooks remain in place as a fail-open backup for the CLI runtime, where they do fire; `cache.py put` is idempotent, so a double-write is safe.) The cache is **internal-only**: never a deliverable, never shown to the teacher, never previewed. The cache schema, keying, freshness gate, and the full persistence contract live in the named agent's body and `${CLAUDE_PLUGIN_ROOT}/references/schemas/digest-cache.md`; they are not restated here.
