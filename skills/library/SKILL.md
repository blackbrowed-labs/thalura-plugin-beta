# /thalura:library — Unit Library (Bibliothek)

> Core protocols — startup, workspace-root resolution, profile load, HiTL/draft lifecycle, class definitions — run via the `core` skill; this task assumes startup has run (`${CLAUDE_PLUGIN_ROOT}/skills/core/SKILL.md`).

The library (Bibliothek) is a permanent, year-independent, per-subject shelf of **read-only unit snapshots** at `<WORKSPACE_ROOT>/data/library/`. It lets a finished, validated teaching unit (Unterrichtseinheit) be reused: shelved once, then assigned to another class or a new school year. All three flows below are **copy-within-the-workspace** operations — no file ever leaves the workspace here.

**Presentation rule (all flows):** interact in `conversation_language`; present **prose previews, never raw `data/` JSON**; select units menu-driven (title + subject + grade + creator). The teacher never types a path, a class identifier, or a `unit_id`.

**Family grouping (one row per family):** every listing of library entries shows **one row per family** — never one row per entry — with title, subject, grade, course level, and creator taken from the family's newest non-archived version (Fassung), plus a version cue when the family has more than one version: *„Globalisation (Englisch, Klasse 10) — 3 Fassungen, zuletzt aufgehoben im Juni 2026."* When the family's newest member was imported rather than shelved here, the cue reads „zuletzt importiert" instead of „zuletzt aufgehoben". A 1-version family shows no cue.

**Consistency check (on read):** when reading `<WORKSPACE_ROOT>/data/library/{subject}.json`, verify every entry's `materials_path` folder exists; report a dangling entry (index points at a missing snapshot) and fix it only on the teacher's explicit confirmation. Additionally verify **link integrity**: every `replaces`/`replaced_by` value names a `unit_id` present in the same subject file. A dangling `replaces` is treated as a **family root**; a dangling `replaced_by` as having no successor; either is reported and fixed (pointer set to `null`) only on the teacher's explicit confirmation — **never silently rewritten**. A dangling link degrades presentation only; it never blocks a flow.

## Flows

| Flow | Scope |
|---|---|
| `shelve-unit` | Copy a finished class-bound unit into the library (strip class binding, drafts, submissions, manifest). |
| `assign-unit` | Copy a library snapshot into a fresh class-bound unit folder and register it in the school-year plan. |
| `library-restore` | Offer an older version (Fassung) as the default again — bring an archived version back into the offered list. |

---

## Version families (Fassungen)

Every library entry is one **version (Fassung)** of a unit. Entries linked by `replaces`/`replaced_by` within a subject file form one **version family**, presented to the teacher as ONE unit. The family is **derived from the links at read time — never stored**: membership follows the links in both directions (a revision's `replaces` pointer alone keeps it in the family, even when its parent's single `replaced_by` names a different revision); an entry with no links is a 1-version family. The family's timeline is ordered by acquisition timestamp — `shelved_at`, falling back to `imported_at` for imported members — never by link-walking. The **default offered version(s)** are the family's non-archived member(s), normally exactly one (the newest). Two revisions may share one parent; that is tolerated — a successor link, once set, is never overwritten, and ordering does not depend on it.

## `unit_id` verify contract

Each library entry's `unit_id` follows `lib_{slug}_{sequence}` (registered in `naming-conventions.json` under `identifiers.unit_id`): `{slug}` = the unit's `unit_slug` lowercased kebab-case; `{sequence}` = a zero-padded three-digit per-slug counter within the workspace, starting `001`. Before writing an entry, the id must pass the gates below — the gates are the contract, the derivation method is free:

1. **Shape gate (pre-write):** the id matches the literal pattern `^lib_[a-z0-9-]+_[0-9]{3}$`.
2. **Uniqueness gate (pre-write):** the id collides with **no** existing entry in any `<WORKSPACE_ROOT>/data/library/*.json` **and** with **no** existing `<WORKSPACE_ROOT>/data/library/materials/{unit_id}/` folder — check **both** the index and the filesystem, because they can drift.
3. **Freshness gate (post-write):** generation is deterministic (the next free sequence for the slug, derived by reading current state), so the freshness analogue is: re-running the generation immediately after the entry is written must yield a **different** id (the next sequence). This proves the generator *samples current state* rather than echoing a cached or fixed value. **On a freshness-gate failure the written entry stands — do not roll it back** (the id was already independently verified unique by gate 2); the failure means the *generator* is broken (echoing, not sampling), so tell the teacher, and any further generation this session must switch to a different derivation method before minting another id.
4. **Verify-then-escalate-or-flag:** if a pre-write gate fails, regenerate the id via a different method (for example, re-derive the sequence by listing the `materials/` folder instead of the index); **never write an unverified id**; if no method passes the gates, stop and tell the teacher rather than shipping a gate-failing id.

A residual remains: two concurrent sessions on the same workspace could race the sequence counter between the uniqueness check and the write. This is accepted for a single-teacher tool — the post-write freshness gate plus the dual index-and-filesystem check bound the damage to a detectable, reportable collision.

## Canonical-key mapping

Library snapshots and bundle payloads use **canonical (locale-neutral) folder keys** — `lessons`, `materials`, `assessments` — never a workspace's localized folder names. Shelving maps the source workspace's localized folders **into** canonical keys; assigning maps canonical keys **into** the target workspace's localized folder names. The mapping table is the `folder_names` block of `${CLAUDE_PLUGIN_ROOT}/references/localization.json`, resolved for the relevant `conversation_language`.

## The `shelve-unit` flow — shelve a unit into the library (eine Einheit in die Bibliothek stellen)

**Trigger examples:** "Einheit in die Bibliothek stellen/aufnehmen", "Einheit für später aufheben", "Einheit wiederverwenden können", "shelve this unit", "save this unit for reuse", "Übernimm meine Änderungen in die Bibliothek", "leg den aktuellen Stand als neue Fassung ab", "fold my changes back into the library".

1. **List** the teacher's units (from school-year plans across years, newest first; show title, class, year, status) and let them pick one. **Only Thalura-generated units with an output folder are shelvable:** a manually-tracked school-year-plan entry has no output folder and no manifest to snapshot from — show such a unit in the list but mark it unshelvable, with a one-line reason (nothing to copy; the entry exists only in the year plan).
2. **Validation gate.** Read the unit's manifest (`plan.json`). The **unit-plan document is the snapshot's required root document:** if it has never been validated (draft-only or absent), shelving cannot proceed — say so and offer the validation flow first. For any *other* tracked document still in draft, list them and ask: validate first, or shelve only the validated documents? **Never silently include a draft.**
3. **Snapshot copy.** After the `unit_id` passes the verify contract above, create `<WORKSPACE_ROOT>/data/library/materials/{unit_id}/` and copy, mapping localized subfolders into canonical keys:
   - **Selection:** copy **only manifest-tracked, validated** documents — the unit-plan document to the snapshot root; tracked lessons into `lessons/`; tracked materials into `materials/`; tracked assessment task and rubric files into `assessments/` (numbered subfolders preserved). Untracked stray files are not copied (report them to the teacher if present).
   - **Exclusions (hard):** **never** copy the unit manifest (`plan.json`); **never** copy any file whose name carries the localized draft suffix (`system_labels.draft_suffix` for the source workspace language, e.g. the German or English form); **never** copy the material-overview document (regenerated on assign); **never** copy the reflection document (a class-bound retrospective).
   - **Submissions exclusion (hard, localized):** resolve the submissions folder name from the **source workspace's `conversation_language`** via `${CLAUDE_PLUGIN_ROOT}/references/localization.json` → `folder_names.submissions`, and exclude that folder **at any depth** inside the assessments folder (flat or numbered-subfolder layouts alike). Do not match on a fixed lowercase folder name. As a belt-and-suspenders sweep, also exclude any folder matching **any** language's `folder_names.submissions` value.
   - **Class-neutral rename (hard):** snapshot filenames are stored **class-neutral**. A resolved document filename opens with the naming pattern's `{subject_abbr}{grade}` block — which **is** the source `class_id` (`E10a - …`) — so every copied file is renamed to strip that class-identifying prefix, resolved from the source unit's naming pattern (teacher overrides in `<WORKSPACE_ROOT>/data/config/naming-conventions.json` included). The verify invariant is: **after renaming, no filename anywhere in the snapshot may contain the source `class_id`.** If a residual match survives (for example, the class identifier happens to appear inside a title), flag it to the teacher and resolve it before the entry is written — never ship a snapshot filename carrying the source class identifier silently.
   - **Post-copy verify:** after copying, verify the snapshot — every `documents`-inventory file exists; **no** submissions folder (any language), **no** draft-suffixed file, **no** manifest, and **no** filename carrying the source `class_id` anywhere in the snapshot. On failure: fix (remove or rename the offender, re-copy) and re-verify; if unfixable, attempt to remove the partial snapshot — when it cannot be removed, name it to the teacher as safe to delete manually — and stop with a prose explanation; never leave a gate-failing snapshot presented as good, and never claim a clean rollback that did not happen.
4. **Version detection (Fassungserkennung) — before the entry is written.** Decide whether this shelve creates a **new version (neue Fassung)** of an existing library unit or an independent entry:
   - **The source manifest carries a `library_ref` that resolves** (its `unit_id` names an entry in the unit's subject file): this shelve is a revision; that entry is the **parent**. Ask, in one message: *„Soll ich diese Einheit als **neue Fassung** von ‚{Titel}' aufnehmen (die bisherige Fassung bleibt erhalten und ist jederzeit wiederherstellbar) — oder als **eigene, neue Einheit**?"* If the `library_ref` does **not** resolve (for example after a workspace restore that left the library out), say so in one honest sentence and fall through to the title match below — never chain `replaces` to an id that resolves to nothing.
   - **No `library_ref`, but a same-title unit (case-insensitive title match or same `unit_slug`, same subject) already exists in the library:** offer the same choice, cueing the existing family: *„In deiner Bibliothek gibt es bereits ‚{Titel}' (zuletzt aufgehoben {Monat Jahr}). Soll ich diese Einheit als neue Fassung dazulegen oder als eigene, neue Einheit aufnehmen?"* — the cue's date verb follows the acquisition („zuletzt importiert" when the family's newest member was imported). On „neue Fassung", the parent is the family's newest non-archived version. When several families match, cue the newest and name the others in one line. The cue is informative, never binding — the teacher decides.
   - **Neither applies:** a plain new entry — no question, no links, `version_note: null`.
   - **Version note (on the neue-Fassung path only):** the same message carries a **proposed version note** — model-authored from (a) the **inventory delta** between the parent's and the new entry's `documents` inventories (lessons added/removed/retitled, duration changes, material count/type changes, assessment changes — computed from the inventories, never by opening document binaries), (b) the source unit's `modification_notes`, and (c) `reflection.improvements` where a reflection exists. The teacher confirms, edits, or strikes it in the same breath — zero additional questions, and the note is **never typed by the teacher** (when the teacher answers in prose, re-phrase and confirm). An explicitly struck note is stored as `null`; a note is **never silently invented**. When all three sources are empty, say so in the same message and offer to record nothing. **Class-neutrality gate:** the confirmed note must not contain the source class identifier (the resolved `{subject_abbr}{grade}` block); on a hit, re-propose without it and confirm again — **never write a note carrying a class identifier** (the note travels when the unit is exported).
   - If the teacher aborts here, handle the already-copied snapshot per step 3's unfixable path (attempt removal; name any unremovable leftover honestly).
5. **Write the library entry** (`source: "self"`, `shelved_at` now, `source_class` = `{year}/{class_id}`, `unit_slug` stored, `competency_areas` and `planned_hours` copied from the school-year-plan unit entry, `documents` inventory with the class-neutral filenames, and `version_note` as confirmed in step 4 — `null` for an independent entry). Append to `units[]` in `<WORKSPACE_ROOT>/data/library/{subject}.json`. **On the neue-Fassung path additionally:** the new entry's `replaces` = the parent's `unit_id`; the parent gets `archived: true` (a no-op if it is already archived) and `replaced_by` = the new `unit_id` **only if its `replaced_by` is currently `null`** — a successor link, once set, is never overwritten. The parent's **materials are untouched**. **On the eigene-Einheit path:** an independent entry, no links — a new family.
6. **Confirm in prose:** what was shelved, what was excluded and why (drafts and student submissions (Abgaben) stay in the class folder), that the original unit folder is untouched — and, for a new version (Fassung), that the previous version remains available and what the recorded note says.

## The `assign-unit` flow — assign a unit from the library (eine Einheit übernehmen/zuweisen)

**Trigger examples:** "Einheit übernehmen/zuweisen", "Einheit aus der Bibliothek", "Einheit nochmal mit der neuen Klasse", "assign a unit from the library", "reuse a shelved unit".

1. **List** the library's unit **families** for the teacher's subjects — one row per family, following the family-grouping presentation rule (title, subject, grade, course level, creator from the newest non-archived version, shelved/imported date, version cue) — and let them pick one. **Empty-library / not-shelved edge (likely first contact):** if the library is empty, or the teacher names a unit that is not shelved (for example "die Globalisation-Einheit vom letzten Jahr übernehmen" when it only exists as a class-bound unit), do not dead-end — explain that assigning works from the library (Bibliothek) and **offer to shelve that unit first**, then continue the assignment with the fresh entry.
2. **Version choice (Fassungswahl) — only when the picked family has more than one version.** Default = the family's newest non-archived version (Fassung). Present the default with its context and make the alternatives one question away, each summarized from `version_note` + acquisition date + class context (from `source_class`, display only) — never a file diff, never ids, never raw JSON; a `null` note is summarized honestly („keine Angaben zu Änderungen"). Example: *„Ich nehme die neueste Fassung vom Juni 2026 (zuletzt mit der 10a verwendet — „mehr Scaffolding für das Essay, neue Hörverstehens-Stunde"). Es gibt noch zwei ältere Fassungen: Juni 2025 (die ursprüngliche Fassung) und Februar 2026 („gekürzt auf 10 Stunden"). Welche soll ich für deine neue Klasse übernehmen?"* Picking an older version is a **first-class, read-only pick**: it does **not** route through the restore flow and does **not** change any `archived` flag — assign never writes the library index; the family's default stays the newest. With multiple non-archived versions (for example after a restore that keeps two offered), the newest is the default and the others are named alongside. A 1-version family skips this step.
3. **Target class:** pick an existing class or create one inline — class creation delegates to the core Class Definition System flow (no re-implementation here).
4. **Suitability gate.** Compare the entry against the target class: `sek_level`/`grade_level` (band-aware) and `course_level` (a `gA` snapshot into an `eA` class, or vice versa) mismatches are **surfaced as prose warnings with explicit confirmation** — never a silent proceed, never a hard block (the teacher decides).
   - **Drafts question (Entwürfe) — only when the entry carries drafts.** When the entry's `draft_documents` inventory is non-empty (in v1 data only an imported / `source: "external"` entry ever carries drafts), ask **once**, after suitability and before the copy: *„Die Einheit enthält N Entwürfe — auch übernehmen? (Sie bleiben als Entwurf markiert, bis du sie prüfst.)"* (`N` = the `draft_documents` count). Ask it **only** when drafts exist — an entry with no `draft_documents` sees no such question and the common assign path is unchanged. The question **may share the same conversational turn as an adjacent confirmation** — the suitability confirmation above, or the target-class selection (step 3) — so it is **never a bare extra round-trip**. The teacher's answer drives the draft copy (step 5) and the draft entries in the fresh manifest (step 6).
5. **Copy.** Copy the snapshot into a fresh `{Subject}/{year}/{class_id}/{Unit_slug}/` (localized subject folder; slug = the entry's **stored `unit_slug`** — the same slug the `unit_id` embeds, never re-derived from the title — de-duplicated against existing folders), **re-localizing canonical keys into the target workspace's `conversation_language`** folder names, and **re-applying the class block for the TARGET class in its pattern position:** each class-neutral snapshot filename gets the target class's resolved `{subject_abbr}{grade}` block placed where the target workspace's naming pattern puts it (an exotic teacher-override pattern may not put the class block first — apply it in the pattern's position, so an assigned copy never carries another class's — or no class's — identifier). The target folder must not already exist (on collision, ask — a different slug or abort).
   - **Validated channel (default) — the drafts region is skipped structurally.** The copy enumerates only the three validated canonical keys (`lessons`/`materials`/`assessments`) plus the unit-plan root document, so an entry's `drafts/` region is **skipped structurally, not by a suffix filter** — a drafts-not-taken assign never touches the region. Region files are **immutable snapshot materials**; no flow treats a region file as a validated document, and only assign (here) and re-export (the unit-exchange task) ever read the region.
   - **Drafts, on „ja" to the step-4 question.** Each file in the entry's `drafts/` region is copied into the target class tree **beside the validated documents, in the same localized subfolders** — a draft lesson into the target's localized lessons folder, a draft material into materials, a draft assessment into assessments; **never** a `drafts/` subfolder in the class tree. The copied files become **ordinary live drafts (Entwürfe)**. Per file: apply the target class's resolved `{subject_abbr}{grade}` block (as for the validated documents), and re-localize the draft suffix **detect-then-replace** — strip the arrived suffix by matching **any** language's `system_labels.draft_suffix` (the same any-language match the import screen uses), then append the **target** workspace language's `system_labels.draft_suffix`. The resulting filename must satisfy the unit manifest's **suffix⟺status consistency invariant** (a `status: "draft"` file carries the draft suffix); a **mis-detected** suffix fails that check and is **flagged to the teacher, never landed silently**.
   - **Drafts, on „nein".** Nothing is copied from the region. Tell the teacher the drafts **stay with the library entry** and can be taken over on a later assign of the **same version (Fassung)** — the entry's region is immutable, so declining now costs nothing later. The fresh manifest then carries only the `documents`-derived (validated) entries.
6. **Regenerate a fresh manifest (`plan.json`):** new `class_id`, `created_at` now, `unit_plan.version: 1`; every **validated** document `status: "validated"` with paths in the re-localized tree (localized folder names + the target-class filenames), each **reconstructed exclusively from the entry's `documents` inventory** — the all-validated rule is scoped to that inventory (the validated channel), never to the draft channel; `material_overview: null` (regenerated on demand later); plus:
   - **Taken-over drafts (only when the teacher answered „ja" in step 4):** the drafts copied in step 5 are registered as **first-class entries with `status: "draft"`** — reconstructed from the entry's `draft_documents` inventory exactly as validated entries come from `documents`, with paths in the re-localized tree (target-language draft suffix + target-class filename block) — and **never** `status: "validated"`. A declined (or absent) draft channel adds nothing here; the manifest then holds only the `documents`-derived entries.
   - `library_ref`: `{ "unit_id": "<the picked version's entry id>", "assigned_at": "<ISO>", "adaptation_complete": false }` — always the **picked** version's id, so a later re-shelve chains from exactly that version.
   - **Gate records (fresh import stub):** every reconstructed document entry (validated and taken-over draft alike) carries the fresh stub `gates` record — `{ "evidence": "imported", "verified_at": "<assign time>" }`, no read-back values — re-verification-exempt per the unit-manifest schema (`${CLAUDE_PLUGIN_ROOT}/references/schemas/unit-manifest.md`); a later revision or validation (Prüfung) writes a real record.
7. **Register in the school-year plan:** add a units entry for the target class (title, `semester` asked or derived, `planned_hours` from the entry, `status: "planned"`, `source: "thalura"`, `competency_areas` **pre-seeded from the entry and confirmed with the teacher**, `output_path` set).
8. **Regenerate the year overview** for the current school year through the Output-Gate Runner: the new school-year-plan entry is a content-mutating write (current-year scope only; The Map owns the contract: `${CLAUDE_PLUGIN_ROOT}/skills/year-planning/SKILL.md` → *Year Overview Document*).
9. **Slot check:** every `duration` slot ID in `documents.lessons[]` — **and, when drafts were taken over, in `draft_documents.lessons[]`** — must exist in the target school configuration; an unknown slot is surfaced and mapped by the teacher before the manifest is written.
10. **Adaptation reminder contract:** the assigned documents are validated **but pedagogically un-adapted** to the new class. Say so in prose. Until the teacher flips `adaptation_complete` to `true`, the unit-planning and lesson-detail flows **remind once per session** when operating on this unit. Any flow may flip the flag on the teacher's explicit say-so ("die Einheit ist angepasst").
11. **Post-copy verify:** every `documents`-inventory file exists in the target tree under the localized folder names **and carries the target class's resolved filename block** (no class-neutral leftovers, no foreign class identifier); the school-year-plan entry and the manifest cross-reference each other (`output_path` ↔ folder; `library_ref.unit_id` → an existing library entry). **Draft branch — assert the answer that was taken:** when the teacher took the drafts over, every taken-over draft exists in the target tree under the localized folder names, carries the **target-language** draft suffix and the **target class's** filename block, and appears in the manifest with `status: "draft"`; when the teacher declined (or the entry had no drafts), **no** `drafts/`-region file appears anywhere in the target tree. On failure: fix and re-verify, or roll the partial assignment back (delete the fresh folder, remove the plan entries) and stop with prose.

## The `library-restore` flow — offer an older version as the default again (eine ältere Fassung wieder als Standard anbieten)

**Trigger examples:** "eine ältere Fassung wieder anbieten", "zur alten Fassung zurück", "archivierte Einheit wiederherstellen", "alte Version aus der Bibliothek zurückholen", "restore the archived unit", "offer an older version again".

Restore changes which version (Fassung) of a unit the library offers by default. It is **not** needed for a one-off older pick — assign's version choice covers that read-only; restore is for moving the family's **default**.

1. **List archived versions, grouped under their family heading** — the family's title once; beneath it each archived version (Fassung) by acquisition date and version note, and what replaced it.
2. Teacher picks one; ask **alongside or swap**:
   - **Alongside:** set `archived: false` (keep the `replaces`/`replaced_by` links as history). The family then offers both versions.
   - **Swap:** set `archived: false` on the restored entry **and** `archived: true` on its `replaced_by` successor (links preserved, direction unchanged). Honest note: in a family with more than two versions or a branched history, the direct successor may already be archived while a newer version stays offered — swap then also leaves the family offering two versions, exactly like alongside; say so rather than promising the default moved.
3. **Entry-metadata-only:** this flow edits index entries only — it **never** touches `materials/{unit_id}/` and **never** deletes an entry.
