# Thalura — Document Specifications (Planning & Reflection)

This document specifies the structural rules for every planning and reflection document that Claude Cowork generates. It defines what sections each document contains, in what order, and with what content. Formatting chrome (page setup, header, footer, font defaults) is applied via `.docx` template files. All layout values behind these documents live in the layout layer: `${CLAUDE_PLUGIN_ROOT}/references/template-specification.md` and `${CLAUDE_PLUGIN_ROOT}/references/design-tokens.json`. This document carries none of them.

---

## Scope

**Covered:** Unit Plan (Einheitenplanung), Lesson Plan (Stundenentwurf), Material Overview (Materialübersicht), Unit Reflection (Reflexion).

**Not covered:** Materials (worksheets, handouts, slides, reading texts) — these use `.docx` template files with `{{DOUBLE_BRACES}}` placeholders, see `skills/material-gen/SKILL.md`. Assessments — structure defined by `exam-formats/*.md`.

**Related files:**

| File | Purpose |
|---|---|
| `output-architecture.md` | Folder structure, naming, draft workflow |
| `naming-conventions.md` | Filename patterns and template variables |
| `localization.json` | Display labels, section headings, filenames |
| `schemas/unit-manifest.md` | `plan.json` schema |
| `glossary-de.md` | Canonical English ↔ German term pairs |

## Shared Conventions

### Heading Hierarchy

| Level | Usage |
|---|---|
| H1 | Document title |
| H2 | Section headings |
| H3 | Subsection headings |

Section headings are resolved via `localization.json` → `planning_sections` based on `content_language`. Skill files reference them as `{planning_sections.key}`.

### Content Language

Section headings and labels use the content language resolved via the fallback chain (core skill satellite `${CLAUDE_PLUGIN_ROOT}/skills/core/content-language-gendering.md`, *Content Language Resolution*). Body content (didactic commentary, differentiation notes, etc.) uses the same resolved content language.

### Template Files

Page setup, header, footer, and font defaults are defined by `.docx` template files stored in `templates/`. Each planning document type has a corresponding template. The header carries the subject, grade, and teacher abbreviation together with the generation date; the footer carries the page numbering. See `${CLAUDE_PLUGIN_ROOT}/references/template-specification.md` for page setup, header/footer placement, and font defaults.

## Document Type 1: Unit Plan (Einheitenplanung)

### Metadata

| Field | Value |
|---|---|
| Generated by | The Holocron (`plan_unit`) |
| Lifecycle | `{unit_plan}_{draft_suffix}.docx` → validated → `{unit_plan}.docx` |
| Location | Unit folder root |
| Template | `template_unit_plan.docx` |

### Sections

#### 1. Cover Page (Deckblatt)

The first page of the unit plan (Einheitenplanung) — no header or footer on this page.

| Field | Source | Example |
|---|---|---|
| Unit title | Teacher input | |
| Subject (Fach) | `subjects.json` → display name | |
| Grade and course level (Klasse/Anforderungsniveau) | Class definition | "S4 eA" or "Klasse 10a" |
| Semester (Halbjahr) | Teacher input / school year plan | |
| Framework topic (Rahmenthema) | Curriculum reference (if applicable, Sek II) | |
| Abitur focus topic (Schwerpunktthema) | Schwerpunktthemen (if applicable, S3/S4) | |
| Duration | Teacher input | "12 Doppelstunden (24 Unterrichtsstunden)" |
| Teacher | `teacher-profile.json` → name + abbreviation | "Lars Weiser (Ws)" |

Fields that do not apply (e.g., Schwerpunktthema for Sek I) are omitted, not shown as empty.

#### 2. Curriculum Anchoring (Bildungsplan-Verankerung)

H2 heading: `{planning_sections.curriculum_anchoring}`

A compact block citing the regulatory foundation of the unit. Each item with page-accurate APA-style citations (APA 7th edition).

Contents:
- Required module / topic area (Pflichtmodul / Themenbereich) — with document name and page numbers
- School-internal curriculum alignment (Schulinternes Curriculum) — topic assignment and expected semester from the school's SiC, with source filename. Present only when SiC is loaded (Layer 6). No APA citation needed (SiC is a school document, not a BSB publication).
- Abitur focus topic (Schwerpunktthema) — if applicable (S3/S4). For S3/S4 courses, A-Heft Schwerpunktthemen take precedence over SiC where conflicts exist.
- Guiding perspectives (Leitperspektiven) addressed — which of W, BNE, D
- Cross-curricular task areas (Aufgabengebiete) addressed — Sek I only
- Cross-references to optional modules (Querbezüge zu Wahlmodulen) — if applicable
- Core competency domains (Kompetenzbereiche) — with document name and page numbers

APA citation format:
> Behörde für Schule und Berufsbildung [BSB]. (2022). *Bildungsplan Gymnasiale Oberstufe: Philosophie* (S. 23–25). Freie und Hansestadt Hamburg.

Items that do not apply (e.g., Schwerpunktthema for Sek I, Aufgabengebiete for Sek II) are omitted, not shown as empty.

#### 3. Overall Unit Objective (Gesamtziel der Einheit)

H2 heading: `{planning_sections.unit_objective}`

One or two paragraphs stating the overarching competency goal for the unit and how it aligns with curriculum standards (Bildungsplan) competency areas. References specific competency domains (Kompetenzbereiche) by name.

Optionally includes a guiding question (Leitfrage) for the unit — a single overarching question that frames the unit's inquiry. Generated when pedagogically appropriate (not mandatory for every unit).

#### 4. Competency Overview (Kompetenzübersicht)

H2 heading: `{planning_sections.competency_overview}`

A table mapping curriculum standards (Bildungsplan) competencies to unit coverage.

**Columns (3):**

| Column | Content |
|---|---|
| Competency Domain (Kompetenzbereich) | The competency area name from the curriculum standards (Bildungsplan) |
| Indicators (Indikatoren) | Specific competency indicators or standards targeted |
| Unit Coverage (Abdeckung in der Einheit) | Which lessons address this competency, and how |

The table contains three row groups, each introduced by a group header row (text in column 1, columns 2–3 empty). The column structure remains identical across all groups.

**Row group 1 — Competency Domains (Kompetenzbereiche):**
One row per curriculum standards (Bildungsplan) competency domain addressed by the unit. No group header row — these rows start the table directly.

**Row group 2 — Guiding Perspectives (Leitperspektiven):**
Group header row: `{planning_sections.guiding_perspectives}`.
One row per applicable guiding perspective (Leitperspektive). The three guiding perspectives (Leitperspektiven) are:
- **W** — Wertebildung / Werteorientierung (values education)
- **BNE** — Bildung für nachhaltige Entwicklung (education for sustainable development)
- **D** — Leben und Lernen in einer digital geprägten Welt (digital literacy)

Column mapping: Column 1 = perspective name + abbreviation, Column 2 = how the perspective is addressed in this unit, Column 3 = per-lesson mapping (which lessons, how).

Only include guiding perspectives (Leitperspektiven) genuinely addressed by the unit content — not all three are required. This row group appears for units at **all levels** (Sek I and Sek II).

**Row group 3 — Cross-Curricular Task Areas (Aufgabengebiete):** *(Sek I only)*
Group header row: `{planning_sections.cross_curricular_task_areas}`.
One row per applicable cross-curricular task area (Aufgabengebiet). Same column mapping as guiding perspectives (Leitperspektiven).

Only for Sek I units (Grades 5–10 and Vorstufe). Include only cross-curricular task areas (Aufgabengebiete) genuinely addressed by the unit content. Omit this row group entirely for Sek II units.

#### 5. Lesson Overview (Stundenübersicht)

H2 heading: `{planning_sections.lesson_overview}`

Per-lesson blocks that serve as a standalone planning reference. Each block provides phase-level detail so the teacher can assess the unit flow from the unit plan (Einheitenplanung) alone; the detailed lesson plans (Stundenentwürfe) provide the full elaboration.

**Block header:** H3 — `{lesson_type} {number}: "{title}" ({duration})`
- `lesson_type` resolved via `localization.json` → `lesson_slots` (Doppelstunde / Einzelstunde)
- Example: `### Doppelstunde 1: "Arrival Stories" (90 min)`

**Phase table** (4 columns):

| Column | Content |
|---|---|
| Phase | Phase name resolved via `localization.json` → `phases` (Einstieg, Erarbeitung, Vertiefung, Sicherung, Puffer) |
| Time (Zeit) | Duration: "10 min", "25 min" |
| Core Activity (Kernaktivität) | Method + core student/teacher activity. Phase guiding questions (Phasen-Leitfragen) appear inline where applicable. Not every phase has a guiding question — only where pedagogically appropriate. |
| Material | Materials referenced: M-numbers for generated materials, or description for standard items |

The Material column's M-number references, and any lesson references elsewhere in this section, render as relative-path hyperlinks to the corresponding material / lesson files per `document-metadata.md` → Referenced-file hyperlinks (root-level linker → `Materialien/…`, `Stunden/…`).

Time allocations must add up to the lesson duration (45 min for single period, 90 min for double period).

**Below the phase table**, two lines:

1. `{planning_sections.key_terms}: {comma-separated list}` — subject-specific key terms (Fachbegriffe) introduced or reinforced in this lesson
2. `{planning_sections.curriculum_reference}: {competency abbreviations with descriptions}` — per-lesson curriculum reference (Bildungsplan-Bezug) using competency indicator abbreviations, e.g., "F2 (Intuitionen hinterfragen), D4 (Argumentationsstrukturen herausarbeiten)". Document-level APA citations are in the curriculum anchoring section (Section 2); per-lesson references use abbreviations only.

#### 6. Didactic Concept (Didaktisches Konzept)

H2 heading: `{planning_sections.didactic_concept}`

250–400 words covering:
- Overarching unit dramaturgy (red thread, narrative arc)
- Focus areas and rationale (course profile, learning group)
- Progression logic and sequencing decisions
- Key methodological decisions and their didactic framing
- Cross-references to optional modules (Querbezüge zu Wahlmodulen) — didactic justification
- Connection to prior and subsequent units (if relevant)
- Prospective reflection: curriculum standards (Bildungsplan) coverage, methodological variety, deliberate scope limitations

#### 7. Differentiation Concept (Differenzierungskonzept)

H2 heading: `{planning_sections.differentiation_concept}`

How differentiation is handled across the unit:
- References to the class definition (special needs, prior knowledge)
- Planned differentiation strategies (scaffold, extension, access levels)
- Which lessons have differentiated materials planned
- References to `special-needs-catalog.md` for specific accommodation (Nachteilsausgleich) measures

## Document Type 2: Detailed Lesson Plan (Stundenentwurf)

### Metadata

| Field | Value |
|---|---|
| Generated by | The Upside Down (`plan_lesson_detail`) |
| Lifecycle | `{number}-{Topic}_{draft_suffix}.docx` → validated → `{number}-{Topic}.docx` |
| Location | `{lessons}/` subfolder |
| Template | `template_lesson_plan.docx` |

### Sections

#### 1. Lesson Header

A key-value block at the top of the first page (not a cover page — content continues below). Presented as a compact metadata block.

| Field | Source | Example |
|---|---|---|
| Lesson number and topic | Unit plan | "Lesson 3: Push and Pull Factors" |
| Type and duration | Unit plan / class definition | "Double period (Doppelstunde) — 90 min" |
| Date | Teacher input (if known) | "12.03.2026" or omitted |
| Class | Class definition | "E-S2-eA (28 students)" |
| Subject | `subjects.json` | "Englisch" |
| Lesson objective (Stundenziel) | Generated by The Upside Down | One sentence stating the primary learning goal |

**Time budget (Zeitbudget):** A single summary line at the end of the header block showing the phase time breakdown at a glance.

Format: `{planning_sections.time_budget}: {t1} + {t2} + {t3} + ... = {total} Min`
Example: `Zeitbudget: 10 + 35 + 20 + 15 + 10 = 90 Min`

When a time buffer (Zeitpuffer) is configured, the plannable time is reduced per lesson segment:
- Continuous double period (90 min), buffer 5 min: plannable = 85 min
- Double with break (45 + break + 45), buffer 5 min: plannable = 40 + 40 = 80 min
Display as: `Zeitbudget: 10 + 30 + 20 + 15 + 5 = 80 Min (Zeitpuffer: 2 × 5 Min)`

Phase times must match the phase table (Verlaufsplan).

#### 2. Placement within the Unit (Einordnung in die Einheit)

H2 heading: `{planning_sections.placement_in_unit}`

A brief paragraph (3–5 sentences) contextualizing this lesson within the unit progression:
- What was achieved in the previous lesson
- How this lesson builds on it
- What the next lesson will address

#### 3. Prerequisite Knowledge Check (Vorwissen-Check)

H2 heading: `{planning_sections.prerequisite_check}`

2–4 sentences documenting what subject-specific prior knowledge students need for this lesson. Generated by The Upside Down in step 10 (cross-topic knowledge check). Documents the result of that check so teachers can verify readiness at a glance.

If scaffolding is needed (info box on worksheet, brief opening explanation, pre-reading), this section states what and how.

#### 4. Phase Table (Verlaufsplan)

H2 heading: `{planning_sections.phase_table}`

The core structural element of the lesson plan (Stundenentwurf). The Holocron provides the initial phase structure (phases, methods, activities, materials, curriculum reference); The Upside Down enriches it with detailed teacher/student activities, social forms, operators, and differentiation.

**Columns (7):**

| Column | Content |
|---|---|
| Phase | Phase name: Opening (Einstieg), Main Phase (Erarbeitung), Consolidation (Sicherung), Deepening/Transfer (Vertiefung/Transfer). Resolved via `localization.json` → `phases`. |
| Time (Zeit) | Duration of this phase: "10 min", "25 min" |
| Content / Activity (Inhalt / Aktivität) | Combined teacher and student activity description. Includes the method used. Operators are integrated into student activity descriptions where appropriate. |
| Social Form (Sozialform) | PL (Plenum), PA (Partnerarbeit), GA (Gruppenarbeit), EA (Einzelarbeit). Abbreviations are language-independent. |
| Media / Material (Medien / Material) | Materials referenced: M-number for generated materials, or description for standard items (textbook, whiteboard). |
| Operators (Operatoren) | Key operators used in this phase with AB level in parentheses: "Erläutern (AB II)", "Beurteilen (AB III)". |
| Differentiation (Differenzierung) | Specific differentiation measures for this phase. If none: "—". References variant letters (A, B) where applicable. |

**Time allocations** must add up to the lesson duration (45 min for single period, 90 min for double period). When a time buffer (Zeitpuffer) is configured, phase times add up to the buffer-adjusted plannable time instead.

**Sub-phases (Sub-Phasen):** Phases may contain sub-phases (Sub-Phasen) — indented rows within their parent phase. Example: a deepening (Vertiefung) phase of 40 min split into setup (5 min), preparation (10 min), discussion (15 min), reflection (10 min). Sub-phase times must add up to the parent phase time. Sub-phase rows use the same 7 columns but the Phase column shows the sub-phase name.

**Phase guiding questions (Phasen-Leitfragen):** Phase guiding questions validated in the unit outline (Grobplanung) must reappear in the Content / Activity (Inhalt / Aktivität) column of the corresponding phase. The lesson plan's phase guiding questions must match those in the unit outline — they are not independently generated.

**Below the table:** A "Curriculum Reference (Bildungsplanbezug)" line stating the regulatory basis for this lesson: document name, page numbers, specific competencies. This applies to the whole lesson, not individual phases.

#### 5. Material Overview for this Lesson (Materialübersicht für diese Stunde)

H2 heading: `{planning_sections.material_overview_lesson}`

Two parts:

**Part A — Materials to create (Zu erstellende Materialien):**

H3 heading: `{planning_sections.materials_to_create}`

A table listing all materials that must be generated for this lesson.

| Column | Content |
|---|---|
| No. | M-number (unit-scoped sequential): M01, M02, ... |
| Material | Name / type: "Worksheet: Push and Pull Factors" |
| Description | Brief content description |
| Source | URL/path for external texts, or "Original creation" |
| Pages | Target page count (used by The Playbook as page limit) |

The No./Material M-number references render as relative-path hyperlinks to the material files per `document-metadata.md` → Referenced-file hyperlinks, computed from this lesson's `Stunden/` location (`../Materialien/…`).

**Rubric (Erwartungshorizont) per material:**

H3 heading: `{planning_sections.rubric}` — followed by the material reference, e.g. "Erwartungshorizont M01"

Directly after each material's row (or after the materials table if only one material), a small rubric table specifying expected outcomes. Every material gets a rubric (Erwartungshorizont).

| Column | Content |
|---|---|
| Criterion / Task (Kriterium / Aufgabe) | What the task asks or what is assessed |
| Expected Performance (Erwartete Leistung) | What a correct/good response looks like |

3–6 rows per material. For materials without explicit tasks (slides, image sets, reading texts), the rubric documents expected learning outcomes or usage success criteria. **Consistency check (CRITICAL):** Every expected performance must be achievable through the material. If the rubric requires something the material doesn't enable, fix either the rubric or the material.

**Assessment note (Bewertungshinweis):** Optionally, a brief paragraph below a rubric table providing didactic hints for evaluation — e.g., "The categorizations are intentionally ambiguous. What matters is the quality of the reasoning, not the 'correct' category." Omitted when not needed — only included when the assessment requires pedagogical context that isn't self-evident from the rubric alone. Localization key: `{planning_sections.assessment_note}`.

**Part B — Standard Supplies (Standardmaterial):**

H3 heading: `{planning_sections.standard_supplies}`

A single line listing everyday classroom supplies needed for this lesson, comma-separated:

> Post-its (3 colours), tape, whiteboard markers, A3 paper

The proposal content for this line is described in `${CLAUDE_PLUGIN_ROOT}/references/schemas/standard-supplies.md` (the optional teacher-maintained standard-supplies list (Standardmaterial)).

#### 6. Didactic-Methodological Commentary (Didaktisch-methodischer Kommentar)

H2 heading: `{planning_sections.didactic_methodological_commentary}`

150–300 words justifying the key didactic decisions for this lesson:
- Why these methods were chosen (with reference to teacher preferences and class observations)
- How the phase structure serves the lesson objective
- Differentiation rationale
- Regulatory basis for content and method choices

Language: resolved via the content language fallback chain (core skill satellite `${CLAUDE_PLUGIN_ROOT}/skills/core/content-language-gendering.md`, *Content Language Resolution*).

#### 7. Differentiation (Differenzierung)

H2 heading: `{planning_sections.differentiation}`

Specific differentiation measures for this lesson:
- Accommodations (Nachteilsausgleich) per student need type (references `special-needs-catalog.md`)
- Which materials have differentiated variants planned (references The Multiverse)
- Scaffolding strategies (sentence starters, vocabulary aids, visual supports)

#### 8. Expected Outcomes (Erwartete Ergebnisse)

H2 heading: `{planning_sections.expected_outcomes}`

What students should have achieved by the end of this lesson:
- Knowledge outcomes (what they know)
- Skill outcomes (what they can do)
- Competency progression (how this advances the unit's competency goals)

Presented as a bulleted list (3–6 items).

#### 9. Notes / Remarks (Notizen / Hinweise)

H2 heading: `{planning_sections.notes_remarks}`

Free-text section for:
- Alternative approaches if time runs short or activities don't work as planned
- Backup activities
- Reminders for preparation (copies needed, room setup, technology check)
- Cross-references to other lessons or materials

#### 10. Lesson Reflection (Stundenreflexion) — optional

H2 heading: `{planning_sections.lesson_reflection}`

Appended after the lesson is taught. Not present in the initial draft. Added via the reflection (Reflexion) flow with a lesson number — a short structured interview (2–3 questions).

Content:
- What went well
- What to change next time
- Time management observations

## Document Type 6: Year Overview (Schuljahresübersicht)

### Metadata

| Field | Value |
|---|---|
| Generated by | Auto-regenerated on every content-mutating write to the current school year's `plan.json` |
| Lifecycle | Always `{year_overview}.docx` — no draft suffix, pure derivative |
| Location | Workspace root |
| Template | `template_year_overview.docx` |

A workspace-wide index of the current school year: one class block per class in the school-year plan, each listing that class's competency coverage (Kompetenzabdeckung) and units (Einheiten). It follows the Material Overview (Materialübersicht) structure as its closest sibling — a pure derivative that is never validated and never hand-edited, regenerated in full on every trigger.

### Sections

#### 1. Header

A compact metadata block at the top (not a cover page):

| Field | Source |
|---|---|
| School year | `plan.json` → `school_year` |
| Teacher | `teacher-profile.json` → name |
| Last updated | Timestamp of last regeneration |

#### 2. Class Blocks

One H2 block per `plans[]` entry in the current school year's `plan.json`. The block heading names the subject (localized via `localization.json` → `subjects`), the grade / course designation and course level where present (from the class definition: `grade_level`, `section`, `course_level`), and the `class_id`.

**Class ordering — canonical deterministic sort.** Blocks appear in a locale-invariant order: `subjects.json` array index → grade band (Sek I numeric grades ascending, then Sek II semester-designated courses) → `section` (nulls last) → `class_id` as the total-order tiebreak. No display-label sorting is used, so two regenerations from identical data produce identical block order in any content language.

Each class block contains, in order:

**a. Abitur countdown (Abitur-Countdown) — conditional.**

A single line showing the remaining weeks until the Abitur exams, present **only** for classes in the final qualification phase per `${CLAUDE_PLUGIN_ROOT}/references/temporal-logic.md` (the phase computation and the semester-designator vocabulary live in that reference; the label is `{planning_sections.year_overview_abitur_countdown}`). Absent for every other class — no empty placeholder.

**b. Competency Coverage (Kompetenzabdeckung)**

H3 heading: `{planning_sections.year_overview_coverage}`

The printable form of the competency coverage that the status overview surfaces in chat, built from the plan entry's `competency_coverage` object together with the units' `competency_areas`. A table with three semantic columns:

| Column | Content |
|---|---|
| Competency domain (Kompetenzbereich) | Localized display label of the competency-area ID (backend key → label via `localization.json`) |
| Coverage (Abdeckung) | The plan-level coverage ratio, rendered as a percentage |
| Covered by (Abgedeckt durch) | The units (by number / short title) whose `competency_areas` include this domain; a domain that no unit covers shows the localized gap marker `{planning_sections.year_overview_coverage_gap}` — gaps are always shown, never omitted (the whole point of the printable coverage view) |

One row per competency-area ID present in the plan entry's `competency_coverage` (the per-subject ID set comes from the subject overlays; no subject's list is fixed here). A freshly-scaffolded class with an empty `competency_coverage` object renders the localized empty-state line `{planning_sections.year_overview_coverage_empty}` instead of an empty table.

**c. Unit List (Einheiten)**

H3 heading: `{planning_sections.year_overview_units}`

A table listing **every** entry in the plan entry's `units[]` — Thalura-planned and manual alike, drafts never omitted. A class with zero units renders the localized empty-state line `{planning_sections.year_overview_units_empty}` instead of an empty table. Five semantic columns:

| Column | Content |
|---|---|
| No. (Nr.) | Sequential unit number within the class |
| Unit (Einheit) | Unit `title`; when the unit's planning document currently exists only as a draft, the localized draft marker (`{draft_marker}`) is appended |
| Period (Zeitraum) | `semester` and `planned_hours` from the plan entry (the schema's time granularity; no invented dates) |
| Status | Localized display of the stored status via `unit_status_labels`: `planned`, `active`, `completed`, and the derived labels — a `completed` unit carrying a non-null `reflection` shows `reflected`, an `active` unit carrying non-null `modification_notes` shows `modified` |
| Planning (Planung) | Affordance form per `document-metadata.md` → *Referenced-file hyperlinks* (relative path, verify-exists-then-emit): `[DOCX]` hyperlinking the unit's unit plan (Einheitenplanung) — the validated file when it exists, else the `_{draft_suffix}` file — plus `[PDF]` when a validated PDF sibling exists. A manual unit (`source: "manual"`, no `output_path`) or a registered unit whose folder holds no unit plan yet stays plain text — no affordance, never a broken link |

#### 3. No Further Sections

No standard-supplies analogue and no per-unit material listing — that detail lives in each unit's own material overview (Materialübersicht). This document indexes units, not the files inside them.

**Degenerate rendering:** a current-year `plan.json` whose `plans[]` is empty renders a header-only file — but only once the file exists at all; its creation is lazy (the first content-mutating write that yields at least the first `plans[]` entry). Once created, the file is never suppressed or deleted by the plugin.
