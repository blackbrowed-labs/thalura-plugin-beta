# School Year Plan Schema

## File Path

```
<WORKSPACE_ROOT>/data/school-years/{YYYY-YY}/plan.json
```

One plan file per school year. Contains all classes and their units for that year.

**Example:** `<WORKSPACE_ROOT>/data/school-years/2025-26/plan.json`

## Field Reference

### Root Level

| Field | Type | Description |
|---|---|---|
| `school_year` | `string` | School year in `YYYY-YY` format (e.g., `"2025-26"`). Matches the folder name. |
| `content_rev` | `number` (integer) | Monotonic content-revision counter for this year's plan. Starts at `0` for a freshly created (empty) plan and increments by exactly 1 on every content-mutating write. Never decreases, never resets. Drives the year-overview freshness check — see *Freshness State*. |
| `plans` | `array` | One entry per class taught in this school year. |
| `year_overview` | `object \| null` | Freshness + output-gate record for this year's generated year-overview document (Jahresübersicht). `null` (or absent) until the overview has been rendered at least once. See *Year Overview Record*. |

### Plan Entry (per class)

| Field | Type | Description |
|---|---|---|
| `class_id` | `string` | Matches the class definition's `class_id` (e.g., `"E10a"`, `"PS4"`). |
| `subject` | `string` | Subject ID: `"english"`, `"philosophy"`, `"psychology"`, `"religion"`. |
| `competency_coverage` | `object` | Aggregated coverage ratios across all units. Keys are competency area IDs (English backend keys). Values are floats 0.0–1.0. Recomputed whenever units change. Used by The Sacred Texts (compliance check). |
| `units` | `array` | Ordered list of units planned or completed for this class. |

### Unit Entry

| Field | Type | Required | Description |
|---|---|---|---|
| `title` | `string` | yes | Unit title. German, teacher-facing. |
| `semester` | `number` | yes | Semester number (1 or 2). |
| `planned_hours` | `number` | yes | Planned teaching hours for the unit. |
| `status` | `string` | yes | `"planned"`, `"active"`, or `"completed"`. |
| `source` | `string` | yes | `"thalura"` (generated by plugin) or `"manual"` (added by teacher). |
| `competency_areas` | `array` | yes | List of competency area IDs addressed by this unit. Feeds into plan-level `competency_coverage`. |
| `output_path` | `string \| null` | no | Relative path from `<WORKSPACE_ROOT>/` to the unit's output folder. Capitalized path. `null` if not yet created. |
| `modified_at` | `string \| null` | no | ISO-8601 timestamp of last modification. `null` if never modified after creation. |
| `modification_notes` | `string \| null` | no | Free-text explaining what was changed and why. `null` if unmodified. |
| `reflection` | `object \| null` | no | The Holocron Log output (unit reflection). `null` if not yet reflected. Note: "reflected" is a **derived** label — a unit with `status: "completed"` and a non-null `reflection` object — not a stored `status` enum value. |

### Reflection Object

| Field | Type | Description |
|---|---|---|
| `completed_at` | `string` | ISO-8601 timestamp of when the reflection was completed. |
| `time_adherence` | `string` | `"under"`, `"on_track"`, or `"over"`. |
| `actual_hours` | `number` | Actual teaching hours spent on the unit. |
| `strengths` | `string` | What worked well. |
| `improvements` | `string` | What to change next time. |
| `reuse_recommendation` | `string` | `"reuse_as_is"`, `"reuse_with_changes"`, `"redesign"`, or `"shelve"`. |

### Year Overview Record

The optional root-level `year_overview` object tracks the freshness of — and the output-gate evidence for — the generated year-overview document (Jahresübersicht) rendered from this plan. The overview is a pure derivative: the teacher never hand-edits it, and it is re-rendered whenever the plan's `content_rev` moves ahead of `rendered_rev`.

| Field | Type | Required | Description |
|---|---|---|---|
| `rendered_rev` | `number` (integer) | yes | The `content_rev` value the year-overview document was last rendered against. The overview is **fresh** iff `rendered_rev == content_rev` — see *Freshness State*. |
| `gates` | `object` | yes | Output-gate record for the year-overview document itself — same shape and enum vocabulary as a generated document entry's gate record in the unit manifest. See *Gate Record* below. |

#### Gate Record (`year_overview.gates`)

Compact, all-English-keyed record of the output gates the year-overview document passed when it was last rendered. Same field set and enum vocabulary as a generated document entry's gate record.

| Field | Type | Description |
|---|---|---|
| `verified_at` | `string` | ISO-8601 timestamp of the gate run that produced this record. |
| `evidence` | `string` | Evidence source: `"verifier"` (the shipped output-gate verifier), `"equivalent"` (an equivalent method used when the verifier was unreachable), or `"imported"` (a fresh stub carried by a copy/import path, re-verification-exempt). |
| `metadata` | `string` | Document-metadata gate outcome: `"pass"`, `"fixed"`, `"flagged"`, or `"n/a"`. |
| `template` | `string` | Template-fidelity outcome, doubling as lineage identity: a `<template id>`, `"workspace-override"`, `"absent-evidenced"`, `"flagged"`, or `"n/a"`. |
| `file_links` | `string` | Referenced-file-hyperlink gate: `"<outcome>:<count>"` where `<outcome>` ∈ `pass \| fixed \| flagged` and `<count>` is the number of links found (e.g. `"pass:1"`); the bare string `"n/a"` when not applicable. |
| `citation_links` | `string` | Regulation-citation-link gate, same composite grammar as `file_links`. `"n/a"` for the year overview, which carries no regulation citations. |
| `pdf` | `string` | PDF-metadata gate outcome: `"pass"`, `"fixed"`, `"flagged"`, or `"n/a"`. |
| `compliance` | `string` | Compliance-check outcome: `"ran:<findings>"`, `"late-ran:<findings>"`, `"skipped-config"`, or `"n/a"`. `"n/a"` for the year overview. |
| `read_back` | `object` | Concrete, falsifiable values read back out of the rendered file (not just verdicts) — e.g. `{ "creator": "<author>", "application": "<authoring app>" }`. |

## Freshness State (`content_rev` / `rendered_rev`)

**Normative.** The year plan carries a monotonic content-revision counter (`content_rev`), and the `year_overview` record carries the revision it was last rendered against (`rendered_rev`). Together they make a skipped year-overview regeneration machine-detectable.

**`content_rev` — the increment rule (this schema owns it).** `content_rev` is a monotonic integer that increments by exactly 1 on **every content-mutating write** to this year's plan. The mutating writes are:

- registering a new unit into a class's `units` (a new unit outline landing in the plan),
- changing a unit's `status` (e.g. `planned` → `active`, or `active` → `completed`),
- recording a unit revision (writing or updating a unit's `modification_notes`),
- assigning a unit from the library into a class in this plan,
- a teacher edit to a unit's planned scope in this plan (its `semester`, `planned_hours`, or `competency_areas`),
- any other write that changes the unit content of a `plans[]` entry.

Writes that do **not** change unit content do **not** increment it: creating the empty plan skeleton (no `plans[]` unit content yet), recomputing the derived `competency_coverage`, and rendering the year overview itself (which only sets `rendered_rev`). Landing a plan verbatim from a backup restore is not a mutating write either — the restored file keeps its stored `content_rev`, and its overview lands with it, so `rendered_rev` still equals `content_rev`.

Trigger-site prose in the writing skills restates this list as reinforcement, but **this schema is the contract**: a writing surface that mutates unit content and fails to advance `content_rev` is non-conforming.

**The freshness invariant (normative).** The year overview is **fresh** if and only if `rendered_rev == content_rev`.

- `rendered_rev < content_rev` → **stale**: the plan changed after the overview was last rendered; the overview must be regenerated, which re-renders the document and sets `rendered_rev = content_rev`.
- `year_overview` absent (or `rendered_rev` absent) while `content_rev ≥ 1` → **stale**: content-mutating writes happened but no overview was ever rendered. This is the known failure hole — it must read as stale, never as "nothing to do".

Staleness is a **repair trigger at every touchpoint that reads the plan**: on reading the plan, a reader that observes a stale overview regenerates it through the year-overview generator and records the repair, rather than silently proceeding over the hole.

**Past-year exemption (normative).** Past school years are read-only. A plan whose `school_year` is not the current school year carries a frozen `content_rev` and is under **no** regeneration obligation: its year overview is never re-rendered on read, and a `rendered_rev` trailing `content_rev` on a past year is **not** a repair trigger. The freshness invariant is enforced for the **current** school year only.

## Competency Area IDs

Competency area IDs are English backend keys (e.g., `functional_communicative`, `intercultural`, `text_media`, `language_awareness`, `language_learning`). Display labels (German) are resolved via `${CLAUDE_PLUGIN_ROOT}/references/localization.json`.

The exact competency area IDs per subject are defined in the subject overlay references. The examples above use English subject competency areas.

## output_path Convention

`output_path` is relative to `<WORKSPACE_ROOT>/` and follows the output path convention:

```
{Subject}/{school_year}/{class_id}/{Unit_slug}/
```

**Sek I example:** `English/2025-26/E10a/Globalisation/`
**Sek II example:** `Philosophy/2025-26/PS4/Existenzialismus/`

Subject and unit slug are capitalized on the filesystem. Backend JSON IDs stay lowercase (`"english"`, `"philosophy"`).

The folder contains `plan.json` (unit-level manifest), localized document files, and subfolders (`Stunden/`/`Lessons/`, `Materialien/`/`Materials/`, `Lernkontrollen/`/`Assessments/`). See `${CLAUDE_PLUGIN_ROOT}/references/output-architecture.md` for the full structure.

## Design Notes

- The plan file is auto-created when a new school year is detected
- `competency_coverage` is recomputed on every unit change — never manually edited
- `reflection` is embedded directly in the unit entry (not a separate file). The detailed `Reflexion.docx`/`Reflection.docx` lives in the unit output folder
- `school_year` in the root is the only place where school year is stored as data — everywhere else it is derived from the folder path
- **`content_rev` is monotonic for the life of the plan file.** It is never reset — not on a new semester, not when units are removed (removing a unit is itself a content-mutating write and increments it). Integer comparison against `year_overview.rendered_rev` is the whole freshness test: cheap, locale-invariant, no content hashing
- **`year_overview` is lazily created.** It is absent until the overview is first rendered; once present it is updated in place on every regeneration (its `gates` record is re-stamped from that render, and `rendered_rev` is set to the current `content_rev`)
- **Derived label — "modified".** There is no stored `modified` status. A unit with `status` set to `active` **and** a non-null `modification_notes` is the "modified" state — a derived/display label computed from those two facts, not a value stored in `status` (exactly parallel to the "reflected" derived label above). The `active` conjunct is load-bearing: `modification_notes` may also appear on a `completed` unit (see the annotated example), so the "modified-in-progress" signal — the one a revision-awareness check consumes — specifically requires the `active` conjunct.
- **Legacy read-tolerance (no forced migration).** Plan files written by plugin versions before the status-vocabulary reconciliation may carry the legacy tokens `in_progress` or `in_progress_modified` in a unit's `status`. Readers treat a legacy `in_progress` as `active`, and a legacy `in_progress_modified` as `active` plus a non-null `modification_notes` (the "modified" state). No migration is forced: a legacy value normalizes to the reconciled vocabulary the next time a skill writes that unit.
- **Recorded-ref locale invariant.** Recorded path references (`units[].output_path`) are stored in the workspace's own `conversation_language` — the localized subject segment always matches the on-disk folder. A backup restored from a workspace with a different `conversation_language` keeps this invariant: the restore rewrites the localized subject segment of each recorded `output_path` on land, so a restored plan's refs are in the restoring workspace's own language and resolve literally against the restored tree. Consumers may therefore resolve recorded refs literally; no locale mapping is needed at read time.
